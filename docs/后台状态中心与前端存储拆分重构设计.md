# 后台状态中心与前端存储拆分重构设计

## 目标

本次重构解决三个根因问题：

1. 状态写入入口分散，导致设置、学习统计和复习反馈存在并发覆盖风险。
2. React UI 的 `storage.ts` 职责过宽，权限、设置、学习、字幕导航和导出逻辑互相牵连。
3. runtime fallback、安全权限和发布门禁存在真实运行风险。

成功标准：

- Background service worker 是设置与学习状态的唯一写入口。
- UI 和 content script 只能通过明确消息协议提交状态变更，直接 storage 写入只保留在只读/迁移兜底或非核心本地 UI 状态。
- React 侧 storage 能按业务边界拆分，并保持现有 UI 调用面稳定。
- 修复 B站字幕 identifiers、字幕 URL allowlist、optional host 撤权 teardown、CI/release gate。
- 完整验证链路通过。

## 方案

### 1. Background 状态中心

在 background 侧新增学习状态消息处理：

- `LEARNING_RECORD_HIT`
- `LEARNING_REVIEW_FEEDBACK`
- `LEARNING_GET_SUMMARY`

这些消息和现有 `SETTINGS_COMMIT` 共用串行队列。写入时以 storage 最新值为基线做 merge，不接受 UI/content 传来的整包旧快照覆盖最新状态。

设置写入保持 `SETTINGS_COMMIT`，但前端写操作不再使用 storage fallback。fallback 仅用于读操作。

### 2. React storage 拆分

把 `react-ui/src/lib/storage.ts` 拆成面向业务的客户端：

- `chrome-storage-adapter.ts`：封装 `chrome.storage`、`chrome.tabs`、`chrome.permissions`、`chrome.scripting` 的基础适配器。
- `settings-client.ts`：设置读写、订阅、迁移入口。
- `learning-client.ts`：学习概览、快速复习、导出所需学习数据。
- `permission-service.ts`：active tab 站点授权、注入、撤权。
- `subtitle-navigation-client.ts`：popup/options 与 content script 的字幕导航通信。
- `vocabulary-export.ts`：生词导出格式化。

为了降低一次性爆炸风险，先建立新模块并让 `storage.ts` 作为兼容导出层；随后逐步迁移内部实现。UI 组件不在第一阶段大面积改 import。

### 3. Content script 写入收敛

content 侧命中统计不再直接写整包 storage，而是通过 `LEARNING_RECORD_HIT` 提交单词命中事件。background 根据最新 storage 合并 `wordStats`、`learningStats`、`reviewQueue` 和 `learningSummary`。

如果 background 消息不可用，content 保留内存状态并记录错误，不把旧快照写回 storage。

### 4. 缓存与反馈一致性

翻译缓存 key 增加 translator 选择状态版本。误替换反馈、曝光状态变化后 bump 版本；content 侧收到版本变化时清空 translation cache 并失效已渲染字幕。

### 5. 安全边界

B站字幕 identifiers 增加 fallback：

- 先读可见环境已有状态。
- 再从 URL 提取 `bvid`。
- 若缺 `cid`，通过 `x/web-interface/view` 获取分 P 信息。

字幕 URL 仅允许 HTTPS 下的 B站/hdslb 字幕相关域名，字幕 JSON 默认不带 credentials。

optional host 授权只允许 HTTPS；撤权成功后向当前 tab 发送 teardown 消息，content runtime 停止 observer、timer、danmaku 和监听器。

### 6. 测试与发布门禁

新增或更新测试：

- React runtime messaging：写操作失败必须 reject。
- Background 学习状态中心：并发 hit/review 不丢状态。
- Subtitle parser：isolated world 缺 `__INITIAL_STATE__` 时仍可用 URL/API fallback。
- Permission service：撤权后发送 teardown。
- CI/release contract：`release:check` 包含 `test:ui`，CI 上传 zip 前跑 zip smoke。

验证命令：

- `pnpm run lint`
- `pnpm run typecheck`
- `pnpm run test`
- `pnpm run test:ui`
- `pnpm run build:extension`
- `pnpm run pack`
- `pnpm run check:extension-package`
- `pnpm run test:extension-smoke:built`
- `pnpm run test:zip-smoke:built`

## 风险控制

- 不一次性改 UI 组件 import，先让兼容层导出稳定。
- 不删除 legacy overlay，除非测试证明未交付路径完全无引用；第一阶段只降低其牵引。
- 对核心状态写入先补测试再改实现。
- 每阶段运行最小相关测试，最后运行完整链路。
