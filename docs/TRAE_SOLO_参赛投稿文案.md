# 正文文案

## 1. 摘要

我用 TRAE SOLO 完成了一个浏览器扩展：Bilibili Subtitle Vocabulary Extension。它可以在 Bilibili 和 YouTube 字幕中低打扰地插入英文词汇，让用户在看视频时被动接触、收藏和复习单词。

这个项目不是简单的字幕翻译插件，而是把“视频观看、字幕语境、词汇曝光、tooltip 反馈、生词本、复习弹幕、学习进度”串成了一个轻量学习闭环。核心目标是：不打断看视频，也能把碎片时间变成英语输入。

## 2. 背景

我平时经常看 B 站和 YouTube 视频，也有背英语单词的需求。但传统背单词 App 有几个问题：

- 需要专门打开 App 学习，主动性要求高；
- 单词和真实语境割裂，容易记住中文释义却不会在场景中识别；
- 看视频和学英语是两个独立动作，很难长期坚持；
- 很多字幕工具偏向整句翻译，解决的是“看懂”，不是“记住”。

所以我想做一个更低打扰的工具：在用户本来就在看的视频字幕中，只替换少量适合学习的中文词为英文词。用户仍然可以顺畅看视频，但会在真实语境里反复遇到单词。

## 3. 实践过程

### 3.1 任务拆解

我把项目拆成了几个阶段：

1. 先做最小可用版本：识别 Bilibili 字幕，把部分中文词替换成英文词；
2. 加入本地词库：支持 CET4、CET6、考研、IELTS、TOEFL 等词库等级；
3. 控制打扰程度：按替换比例、单句上限、目标 CEFR 难度筛选词；
4. 做交互反馈：用户 hover 单词时显示释义、音标、等级，并支持“认识 / 模糊 / 不认识 / 收藏 / 跳过 / 替换不合理”；
5. 做学习闭环：生词本、快速复习、复习弹幕、连续学习 streak；
6. 做多入口 UI：Popup、Options、视频内 Overlay 共享同一套设置和学习状态；
7. 做工程化发布：Manifest V3、权限收敛、测试、打包、release check。

### 3.2 SOLO 在流程中做了什么

TRAE SOLO 主要参与了这些工作：

- 帮我把“字幕背单词”这个模糊想法拆成可实现的浏览器扩展模块；
- 快速生成和重构 content script、词库匹配、字幕解析、React UI 等代码；
- 根据实际 bug 反复定位问题，例如字幕 DOM 动态更新、视频切换、active tab 连接过期、字幕导航状态不同步；
- 帮我补充测试，包括词库匹配、渲染、学习状态、复习弹幕、权限策略、浏览器扩展 smoke 测试；
- 帮我梳理发布前检查流程，保证项目不是只能本地跑的 demo，而是能打包、能验证、能交付的扩展。

### 3.3 核心实现思路

项目采用 Chrome Manifest V3 浏览器扩展结构：

- content script 负责读取字幕、替换文本、挂载 tooltip、同步视频播放状态；
- background service worker 负责设置初始化、快捷键、消息转发和 storage 写入；
- React + TypeScript 负责 Popup、Options、视频内 Overlay；
- 本地 JSON 词库负责词义匹配，不依赖远程翻译 API；
- chrome.storage.local 保存设置、生词本、复习队列和学习进度。

扩展默认只注入 Bilibili 和 YouTube，不默认全站运行。非默认站点需要用户主动授权后才会启用网页正文模式。

### 3.4 关键功能

#### 字幕词汇替换

扩展会在字幕中查找适合替换的中文词，并替换为英文词。替换不是随机的，会综合考虑：

- 当前启用词库等级；
- 目标 CEFR 难度；
- 词频和考试权重；
- 用户是否已经收藏、掌握或跳过；
- 最近是否频繁出现；
- 用户是否反馈过“替换不合理”。

默认替换比例较低，并限制单句替换数量，避免字幕变得难以阅读。

#### Tooltip 学习反馈

用户把鼠标移到替换后的英文词上，可以看到：

- 单词；
- 中文释义；
- 音标；
- 词性；
- 词库等级；
- CEFR 难度；
- 原字幕语境。

同时可以标记“认识 / 模糊 / 不认识 / 收藏 / 跳过 / 替换不合理”。这些反馈会进入本地学习状态，并影响后续替换策略。

#### 生词本与快速复习

Popup 中可以看到今日学习进度、最近遇到的单词、生词排行和快速复习卡片。用户不需要离开当前视频页面，就能进行轻量复习。

#### 复习弹幕

我把 Bilibili 的弹幕文化也转化成了学习机制：插件可以把已遇见或已收藏的词以弹幕形式从视频画面中飘过。弹幕速度、密度都可以配置，并且会在视频暂停时停止。

这让复习不再是独立任务，而是自然融入视频观看流程。

#### 视频内 Overlay 面板

扩展在视频页面中提供一个悬浮学习面板，可以直接调整：

- 字幕替换开关；
- 替换比例；
- 单句替换上限；
- 目标难度；
- 复习弹幕开关；
- 弹幕速度和密度；
- 今日进度；
- 最近词汇；
- 字幕上一句 / 重播本句 / 下一句导航。

#### 隐私与权限

项目没有自有服务器、没有账号系统、没有广告、没有遥测，也不调用远程翻译服务。设置、生词、复习队列和学习指标都保存在浏览器本地。

默认权限只覆盖：

- Bilibili 视频页；
- Bilibili 官方播放器 / 字幕 API；
- YouTube 页面。

这能降低用户对浏览器扩展权限的顾虑。

### 3.5 中间踩过的坑

1. 字幕 DOM 更新不稳定
   视频平台的字幕不是静态文本，播放器会频繁替换 DOM。最开始只监听一次 DOM 很容易失效，后来加入 MutationObserver、timeline polling 和视频事件同步。

2. Bilibili 视频切换后的状态过期
   单页应用切换视频时，active tab 和字幕导航可能还保留旧状态。后来针对 stale reconnect、stale subtitle snapshot、video key fallback 做了多轮修复。

3. 替换太多会影响观看体验
   初版替换密度偏高，字幕可读性下降。后来加入替换比例、单句上限、核心词库模式、CEFR 目标和自适应调优。

4. 浏览器扩展权限容易过度
   最开始可以很容易做成全站注入，但这对用户不友好。最后改成默认只支持 Bilibili / YouTube，其他站点必须主动授权。

5. React UI 和 content script 状态同步复杂
   Popup、Options、Overlay、content script 都会读写设置。后来把共享设置、runtime 消息、storage 写入队列做了统一处理。

## 5. 效果与总结

这个项目最大的变化，是把“背单词”从一个需要主动打开的任务，变成了看视频时自然发生的微学习事件。

传统流程是：我先看视频，之后再专门背单词。现在变成：我看视频时就能在真实字幕语境里遇到词、标记词、收藏词、复习词。它没有强迫我中断视频，也没有把整句字幕变成难读的中英混杂文本，而是通过低密度插入控制认知负担。

TRAE SOLO 在这个过程中最有价值的地方，不只是生成代码，而是帮助我持续把一个想法推进成完整产品：从字幕替换 demo，到有设置、有反馈、有复习、有权限策略、有测试、有发布流程的浏览器扩展。

我沉淀下来的可复用方法是：

1. 先把真实场景说清楚，不急着堆功能；
2. 先做低成本 MVP，再围绕用户体验补闭环；
3. 对浏览器扩展这类产品，权限和隐私要从一开始就设计；
4. AI 适合承担重复的工程化工作，但每一步都要用测试和真实运行结果校验；
5. 好的 AI 编程流程不是“一次生成”，而是“拆解、实现、验证、修复、再验证”的循环。

最终这个项目让我看到，AI 编程真正提高效率的地方，是把个人开发者原本很难完整覆盖的产品、工程、测试和发布流程串起来。

## 正文

我用 TRAE SOLO 做了一个 Chrome / Edge 浏览器扩展：Bilibili Subtitle Vocabulary Extension。它可以在 Bilibili 和 YouTube 字幕中低打扰插入英文词汇，让用户在看视频时自然接触、收藏和复习单词。

我做这个项目的原因很简单：传统背单词 App 需要主动打开，和真实语境割裂；而视频字幕本身就是很好的语言输入场景。所以我希望把“背单词”从一个独立任务，变成看视频时顺手发生的微学习事件。

实现过程中，我把任务拆成了几个模块：字幕解析、词库匹配、替换策略、tooltip 反馈、生词本、复习弹幕、Popup、Options、视频内 Overlay、权限控制和测试发布。SOLO 帮我从需求拆解到代码实现，再到 bug 修复和测试补齐，持续推进这个项目从 demo 变成可安装使用的浏览器扩展。

项目目前支持 CET4、CET6、考研、IELTS、TOEFL 多级词库；可以按替换比例、单句上限和 CEFR 目标控制学习强度；hover 单词可以查看释义、音标、词性和原句；用户可以标记认识、模糊、不认识、收藏、跳过或替换不合理；收藏词会进入生词本，并能通过 Popup 快速复习或以弹幕形式重新出现。

我比较满意的几个点是：

1. 它不是整句翻译，而是低密度词汇插入，尽量不破坏观看体验；
2. 它有学习反馈闭环，用户操作会影响后续替换策略；
3. 它把 B 站弹幕文化变成了复习机制；
4. 它没有自有服务器，不需要账号，不上传学习数据；
5. 默认只注入 Bilibili 和 YouTube，其他站点必须主动授权；
6. 项目有单元测试、UI 测试、浏览器扩展 smoke 测试、zip smoke 和 release check。

这次实践最大的收获是：AI 编程不只是帮我写某段代码，而是帮我把一个真实场景拆成可落地的产品和工程流程。通过“拆解、实现、验证、修复、再验证”的循环，一个个人想法也可以逐步变成完整工具。
